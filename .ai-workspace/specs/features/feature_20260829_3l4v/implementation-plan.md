2. **从“浅层断言 (Happy-Path)”转向“冷重载 (Cold-Reload) 与持久化闭环”金标准**：
   - **痛点**：AI 生成的测试用例往往仅断言返回的 JSON/VO（内存值），忽略了持久化失败（未落库）导致重启/重登后数据回滚的致命缺陷。

3. **从“局部 20 行 Diff 审查”转向“8 维行为影响拓扑 (Mode D) 自动化驱动”**：
   - **痛点**：在已有复杂系统（如商城、礼包、活动）上新增分支时，AI 审查容易陷入“只看改动行”的管道视野，忽略了绕过上游通用校验（No-Bypass）或跨周期限购脏数据固化问题。

4. **建立“缺陷防线记忆库 (Defect Pattern Memory)”自动反哺机制**：
   - **痛点**：Review 打回或 Bug 修复（BTF 闭环）后，踩坑经验随着 Session 结束而丢失，后续开发容易重蹈覆辙。

### 四、 异常防范、边界条件与自动化测试门禁 (Edge Cases & Verification Strategy)

#### 4.1 边界情况与防御机制 (Edge Cases & Safeguards)

1. **静态扫描误报与特殊语法豁免 (False-Positive Protection)**：
   - *风险*：某些框架底层类合法使用静态导入，或测试类中无需调用持久化。
   - *防范*：在 [`scripts/guard-code-quality.ps1`](file:///D:/project/agent-sop/scripts/guard-code-quality.ps1) 中支持源码级行内注释豁免 `// ai-sop-lint-disable: RULE_ID [原因]` 以及根据文件路径（如 `src/test/**`）自动应用白名单规则。
2. **Reviewer 恶意/敷衍放行 (Shallow Approval Prevention)**：
   - *风险*：Reviewer Agent 仅输出一句 "LGTM" 即提交 `APPROVED`。
   - *防范*：[`schemas/review-mailbox.schema.json`](file:///D:/project/agent-sop/schemas/review-mailbox.schema.json) 与 [`scripts/review-mailbox.ps1`](file:///D:/project/agent-sop/scripts/review-mailbox.ps1) 强制要求 `qualityRubric` 的 6 个维度均有非空分析文本，若检测到重复模板文本或字数过短直接抛出 `SchemaValidationError`。
3. **两阶段提交与 Crash 回滚保护 (Transaction Integrity)**：
   - *风险*：在静态校验或 Mailbox 状态写入过程中进程异常崩溃导致状态文件损坏。
   - *防范*：所有状态文件修改必须通过 `Invoke-AiSopWorkflowTransaction`（两阶段事务提交机制，经 `.tmp` 预写及 `ai-sop-lock` 保护），确保状态一致性。

### 1. 静态门禁解耦与多语言兼容性 (Linter Modularization & False-Positive Guard)
- **解耦设计要点**：`agent-sop` 作为通用 OS 级治理框架（支持 Java, Go, Python, Rust, C++, Web 等），硬编码特定业务方法（如 `updateAirData`、`costOnePiece`）属于架构反模式。
  - **架构对齐建议**：`guard-code-quality.ps1` 必须采用 **“通用核心规范 + 项目可扩展规则集 (`.ai-sop/rules/*.json` 或参数配置)”** 设计。核心通用规则负责通用 AST/正则安全检查，项目业务规则通过扩展机制挂载。
- **多语法豁免注释支持**：代码内豁免指令 `ai-sop-lint-disable: RULE_ID [原因]` 需原生支持不同语言的注释语法：
  - `//`（Java / C++ / Go / Rust / TS / C#）
  - `#`（Python / Bash / PowerShell / YAML）
  - `<!-- -->`（XML / HTML / Markdown）
  - `--`（SQL / Lua）

### 2. 测试断言分类与冷重载金标准 (Cold-Reload Oracle & Backward Compatibility)
- **断言深度与场景分流**：
  - “发请求 $\rightarrow$ 从存储重新冷查询 $\rightarrow$ 断言实体字段”是规避缓存脏数据和未落库 bug 的金标准。
