# 发现追踪与审查材料

这些工具辅助现有 T1/T2/T3，不改变 Complete、批准、归属或人工授权。审查导出不运行测试，不改任务状态，也不替审查者作结论。

## 跨任务发现

在规格仓 `features/<Feature>/findings/<稳定编号>.json` 保存一项发现，格式见 `schemas/finding.schema.json`。它是受版本控制的普通项目资料，不是执行权限或任务完成状态。沿用来源编号，不按修复轮次或新任务复制一份。字段包含严重程度、触发链、影响、来源仓库/版本/文件、宿主相对路径 scope、修复任务/提交/回归 runId、关闭依据和状态历史。

- `OPEN`：确认问题尚未解决；新任务 PASS 不改变此状态。
- `IN_REVIEW`：修复已实施，正在核对修复与回归证据。
- `CLOSED`：有对应修复提交、真实回归及关闭依据；需要独立审核的任务还要关联审核结论。控制器核对原始证据后更新，不能仅凭字段齐全关闭。
- `DISMISSED`：证据表明误报、重复或不适用，保存原因与依据；不是偷偷删除问题，也不自动要求人工批准。

再次出现时恢复 `OPEN` 并追加重开原因，保留原修复历史。`history` 和 Git 版本共同保留变更轨迹。文件更新按当前任务已有写入权限进行，新增立即登记版本控制。不要直接修改历史 task.json。

开始修改时按实际范围查看相关未关闭发现；未知范围标为未判断。路径匹配只是提示，重命名、跨模块耦合仍由执行者判断。无关历史发现不阻塞当前任务。已有 FollowUp 继续管理文档、用例及验证待办，不把源码缺陷伪装成 verification 待办。

## 只读导出

宿主项目根运行：

```powershell
pwsh -NoProfile -File ./.ai-sop/scripts/export-review.ps1 -WorkspacePath . -Feature Example -TaskId change-one -CheckCurrent -Scope src
```

Feature/taskId 替换为实际任务；省略 CheckCurrent 只展示已记录事实，明确标为 NOT_CHECKED。Scope 是宿主相对文件或目录；省略时列出潜在相关发现并标明未筛选。跨仓项目通过 RepositoryPaths 显式列出宿主内的独立仓库，不能把父仓库的成功当成嵌套仓库成功。

结果派生于任务、输入清单、Git 版本/差异索引、原始报告引用、现有 evidence.json 和发现记录。缺失、损坏、跨机不可见或没有基线明确显示 UNAVAILABLE/MISSING；保留同批全部失败历史。输入 MATCH 只表示输入摘要一致，不证明断言、业务语义、清理或代码审核正确。没有报告映射时不猜测实际执行的测试方法。

工具默认输出 JSON，可由调用者存入本机审查目录；不修改任何权威记录。不要把输出复制成第二份手工维护的 task 状态。命令参数、环境变量和原始日志不自动打包；日志与补充证据仅输出引用及摘要，分享前仍核对资料范围。

补充 evidence.json 必须是 JSON 对象。语法损坏或顶层为 null、数组、字符串等非对象时，仅该材料标为 UNAVAILABLE 并附 SUPPLEMENTAL_EVIDENCE_UNREADABLE 诊断；继续输出有效任务历史及发现。未能读取的清理结果、未验证范围保持 NOT_RECORDED，不据此判断通过，也不回写原材料。

## 组合故障检查

涉及进程、事务、锁、外部资源时，从实际调用链选择关键组合：主操作失败后补救是否还能失败；控制器此时退出，恢复身份是否已落盘；换一个执行者能否继续，并且不伤害其他资源。覆盖“首故障→补救再失败→退出→重新进入”中的相关边界，不枚举所有排列。

断言最终恢复不变量：没有遗漏资源、没有误处理其他归属、重复恢复可安全执行、未知结果明确保留，不能只断言 catch 被执行或函数被调用。区分进程内替身、独立控制器、真实业务进程与真实存储；单故障通过不能证明组合通过。夹具归宿主，通用规则不写入具体业务协议和数据库表。

## 验证入口说明

在现有 Profile 说明旁记录：环境前提、创建/修改的资源、隔离方式、清理方式、失败后保留资料、通过能证明与不能证明的范围。优先复用宿主现有说明，不为每个命令增加批准或门禁；已有授权沿用，确有新范围才澄清。verification-commands.json 保持执行配置，说明不作为副作用自动许可。

## 按需干净检出

新增源码、依赖、生成文件或交付发布时，从明确提交在独立空目录检出并构建。记录每个独立仓库/子模块的提交、工具链及必要配置/生成步骤。不得复制工作树未跟踪源码或旧 build/target/classes；仅有本地依赖缓存并不保证可重现，注明使用的缓存和未锁定外部依赖。

结果只绑定实际检出版本；构建成功不证明业务环境启动或测试行为。小改动不默认运行，失败保留材料与准确原因，不靠补拷本机缺失文件让结果变绿。实际入口及环境依赖由宿主明确配置。

`scripts/verify-clean-checkout.ps1 -ManifestFile <清单JSON> -Destination <尚不存在的隔离目录>` 执行这一操作。它会克隆指定仓库、执行明确的构建命令，并保留 checkout 和 evidence/result.json；这不是只读导出工具。清单格式：

```json
{
  "schemaVersion": "1.0",
  "repositories": [{"path": ".", "source": "仓库URL或本机Git仓库", "revision": "实际40位提交"}],
  "command": {"executable": "mvn", "arguments": ["-B", "-DskipTests", "test-compile"], "workingDirectory": ".", "timeoutSeconds": 1800},
  "environmentNotes": "说明实际工具链、依赖缓存及必要环境；禁止写入口令"
}
```

占位符必须替换。根仓库列第一项，嵌套仓库按父目录在前顺序列出并指定各自提交；路径必须位于隔离检出根下，且目标目录不存在。唯一例外是父仓索引明确声明且提交匹配的空 gitlink 占位目录；工具校验后填充，不递归删除已有目录。检出和审查入口拒绝经过链接的后代路径，避免不同平台中间目录链接解析差异。

工具不会自动拉取子模块或猜测未登记依赖，也不会删除失败目录。外部清单只读一次，原字节摘要、保留快照和实际命令来自同一版本。输出成功前核对构建命令的含义；命令返回零本身不证明执行了测试。仓库URL与命令参数可能出现在私有日志或清单中，应使用凭据管理器及环境注入，不将秘密写入清单。导出只排除约定的结构字段，不承诺自动识别作者写进标题或目标等自由文字中的秘密；分享前核对脱敏结果及版本映射。
