# 发现追踪与审查材料

这些工具辅助现有 T1/T2/T3，不改变 Complete、批准、归属或人工授权。审查导出不运行测试，不改任务状态，也不替审查者作结论。

## 跨任务发现

在规格仓 `features/<Feature>/findings/<稳定编号>.json` 保存一项发现，格式见 `schemas/finding.schema.json`。它是受版本控制的普通项目资料，不是执行权限或任务完成状态。沿用来源编号，不按修复轮次或新任务复制一份。字段包含严重程度、触发链、影响、来源仓库/版本/文件、宿主相对路径 scope、修复任务/提交/回归 runId、关闭依据和状态历史。

- `OPEN`：确认问题尚未解决；新任务 PASS 不改变此状态。
- `IN_REVIEW`：修复已实施，正在核对修复与回归证据。
- `CLOSED`：有对应修复提交、真实回归及关闭依据；需要独立审核的任务还要关联审核结论。控制器核对原始证据后更新，不能仅凭字段齐全关闭。
- `DISMISSED`：证据表明误报、重复或不适用，保存原因与依据；不是偷偷删除问题，也不自动要求人工批准。

再次出现时恢复 `OPEN` 并追加重开原因，保留原修复历史。`history` 和 Git 版本共同保留变更轨迹。文件更新按当前任务已有写入权限进行，新增立即登记版本控制。不要直接修改历史 task.json。

开始修改时按实际范围查看相关未关闭发现；未知范围标为未判断。路径匹配只是提示，重命名、跨模块耦合仍由执行者判断。无关历史发现不阻塞当前任务。已有 FollowUp 继续管理文档、用例及验证待办，不把源码缺陷伪装成 verification 待办。

## 只读导出

宿主项目根运行：

```powershell
pwsh -NoProfile -File ./.ai-sop/scripts/export-review.ps1 -WorkspacePath . -Feature Example -TaskId change-one -CheckCurrent -Scope src
```

Feature/taskId 替换为实际任务；省略 CheckCurrent 只展示已记录事实，明确标为 NOT_CHECKED。Scope 是宿主相对文件或目录；省略时列出潜在相关发现并标明未筛选。跨仓项目通过 RepositoryPaths 显式列出宿主内的独立仓库，不能把父仓库的成功当成嵌套仓库成功。

结果派生于任务、输入清单、Git 版本/差异索引、原始报告引用、现有 evidence.json 和发现记录。缺失、损坏、跨机不可见或没有基线明确显示 UNAVAILABLE/MISSING；保留同批全部失败历史。输入 MATCH 只表示输入摘要一致，不证明断言、业务语义、清理或代码审核正确。没有报告映射时不猜测实际执行的测试方法。

工具默认输出 JSON，可由调用者存入本机审查目录；不修改任何权威记录。不要把输出复制成第二份手工维护的 task 状态。命令参数、环境变量和原始日志不自动打包；日志与补充证据仅输出引用及摘要，分享前仍核对资料范围。

补充 evidence.json 必须是 JSON 对象。语法损坏或顶层为 null、数组、字符串等非对象时，仅该材料标为 UNAVAILABLE 并附 SUPPLEMENTAL_EVIDENCE_UNREADABLE 诊断；继续输出有效任务历史及发现。未能读取的清理结果、未验证范围保持 NOT_RECORDED，不据此判断通过，也不回写原材料。

### 按需增量复审

同一导出命令可加 `-PreviousReview <工作区相对的旧导出JSON路径>`。保存的旧报告只作显式比较参考，不证明它已获审核通过。新输出保留完整历史、当前输入匹配、报告引用和未解决发现，另附 incremental：旧报告原字节摘要、逐仓旧/新提交、提交间文件状态差异、两次工作树变化列表及当前最新 runId。输出仍放本任务 specs/evidence，避免进入源码输入扫描。

只有提交间差异可重建。旧报告中的脏文件/未跟踪文件没有保存内容，任一侧存在这些变化时标 COMMIT_DIFF_WITH_WORKTREE_LIMITS，不能声称已覆盖两次工作树的全部差异。旧报告中的仓库本次未选择时显式列为 NOT_SELECTED，整体 PARTIAL；这不表示仓库已删除。空选择、缺仓、提交不可读、HEAD漂移或非法旧报告明确显示缺口，完整导出其他资料继续可用。默认不传参数为 NOT_REQUESTED，不新增门禁或自动复用旧PASS；文件列表不能自动证明哪些测试足够，也不能替审查者作结论。

### 复用边界用例

测试夹具 `scripts/tests/fixtures/boundary-cases.ps1` 提供对象/非负数字的 JSON 类型边界和本机绝对路径、上级越界反例。消费者选择与真实接口相关的用例，调用真实入口并检查业务结果、失败历史和只读性；不是仅断言 helper 返回了预期值。当前用于补充证据、增量报告、附件清单和历史时长。合法 JSON 不代表类型正确；布尔值、数字字符串不能充当时长。绝对路径从本机临时目录生成，不把 Windows 盘符字符串当作所有平台的绝对路径。进程升级、恢复和组合故障仍沿用原有专项夹具，不强行并入数据类型表。

## 减少验证和收尾返工

定稿前可给现有 `export-review.ps1` 加 `-AttachmentsManifest <工作区相对附件清单>`，复用打包所需的JSON文件路径数组。finalization只派生最新验证记录、当前输入是否已确认、所声明材料是否观察到提交字节匹配，以及显式文件/简单Markdown本地链接是否缺失。正文内联链接会检查，代码示例、外部链接、引用式链接和复杂Markdown不作为完整扫描范围；单份Markdown超过1MiB记为不可检查。缺失或异常逐项提示，不中断完整审查导出、不新增Complete门禁，也不把文档存在当作审核批准。

本地链接包括相对路径、本机绝对路径及无主机名的本地 `file:///` URI；Windows 的 `C:/...`、`C:\...` 和 `/C:/...` 不作为网址跳过。相对路径以文档所在目录为基准，绝对路径直接解析，仍只检查工作区内且不经过链接后代的目标。缺失记 MISSING，越界、网络共享、带主机名的file URI（包括localhost）和非 Windows 上的 Windows 绝对路径记 UNAVAILABLE；不访问网络共享。路径中的空格等字符须按链接语法编码。网页协议与锚点继续跳过，提示仍非阻断。这不扩展为完整 Markdown 语法或跨平台实跑承诺。

每份已扫描Markdown增加linkCoverage：可识别候选数、尝试核对的本地链接数、跳过数及原因；links附原始行列，skippedLinks仅记录位置和原因，不复制外部URL或代码示例内容。原因区分外部协议、锚点、行内/围栏代码及已识别但不支持的语法。零个本地候选标NO_SUPPORTED_LOCAL_LINKS，不能解释为链接内容已验证；统计只覆盖可识别候选，不声称覆盖所有Markdown。本地链接的MISSING/UNAVAILABLE仍由逐项状态解释，文件存在与链接检查分开呈现，不新增门禁。

边界夹具Get-AiSopEquivalentLocalLinkCases生成同目标的相对/绝对/file URI及本机Windows写法，消费者实际验证“缺失→创建→删除”和越界时的结果一致。它不共享生产解析器，也不替消费者决定哪些路径应接受；保留此前单点反例，避免测试只证明夹具与自身一致。

先写完并审核文档、审核记录和待执行步骤的准确措辞，再运行该只读提示并一次打包。不要把“测试记录通过”“本地包已生成”“提交字节一致”“已推送”合写为一个手工PASS。finalization中的package/remote保持NOT_CHECKED，因为这个入口不核验包、不联网；提交字节只依据本次显式DeliveryManifest实际检查结果，空清单不证明完整交付。包是生成时的派生快照，Complete之后以外层任务和Git/远端事实为准，不为了更新包中状态反复打包。

先完成定向回归、静态审核以及受影响文档/用例同步，再运行最终全量。运行前用现有导出入口的 `-CheckCurrent` 观察输入和各仓差异；`preparation` 仅汇总当前摘要、最新runId和非阻断提示，不锁文件、不授权自动复用结果，也不替代命令定义与用例范围校验。观察后发生输入修改仍按原规则判定，不忽略文档或改写旧失败。各仓workingChanges可能包含他人的工作，不能直接作为自动暂存清单。

Complete前写完发现关闭依据、审核记录、文档和材料索引。Complete结果由task.json权威记录，后续提交/推送用Git版本与只读交付核对确认，避免再编辑一份手写完成状态。以上是执行顺序和派生提示，不增加任务阶段、审批或完成门禁。

证据安全测试的失败路径保留隔离夹具、逐场景子进程输出及failure.json；逐项尝试有界清理，补救失败不能覆盖原始异常或跳过其他清理。只有断言通过且清理确认时删除夹具。保留现场不是保留运行进程，也不应自动收集环境变量或上传原始日志。

现有Inputs诊断增加路径解析与内容哈希耗时（诊断本身也有开销）。起点采集仍为T2默认500ms/8MiB；路径优化只复用本次已解析根目录，每个输入仍解析物理路径、核对边界并读取内容。超过字节上限的大工程即使提速仍为UNAVAILABLE；需要完整起点时，在修改前使用已有Start -CaptureBaseline。禁止用修改后的Run快照补成起点，或跨调用复用时间戳/文件大小缓存。

## 组合故障检查

涉及进程、事务、锁、外部资源时，从实际调用链选择关键组合：主操作失败后补救是否还能失败；控制器此时退出，恢复身份是否已落盘；换一个执行者能否继续，并且不伤害其他资源。覆盖“首故障→补救再失败→退出→重新进入”中的相关边界，不枚举所有排列。

断言最终恢复不变量：没有遗漏资源、没有误处理其他归属、重复恢复可安全执行、未知结果明确保留，不能只断言 catch 被执行或函数被调用。区分进程内替身、独立控制器、真实业务进程与真实存储；单故障通过不能证明组合通过。夹具归宿主，通用规则不写入具体业务协议和数据库表。

## 验证入口说明

在现有 Profile 说明旁记录：环境前提、创建/修改的资源、隔离方式、清理方式、失败后保留资料、通过能证明与不能证明的范围。优先复用宿主现有说明，不为每个命令增加批准或门禁；已有授权沿用，确有新范围才澄清。verification-commands.json 保持执行配置，说明不作为副作用自动许可。

## 按需干净检出

新增源码、依赖、生成文件或交付发布时，从明确提交在独立空目录检出并构建。记录每个独立仓库/子模块的提交、工具链及必要配置/生成步骤。不得复制工作树未跟踪源码或旧 build/target/classes；仅有本地依赖缓存并不保证可重现，注明使用的缓存和未锁定外部依赖。

结果只绑定实际检出版本；构建成功不证明业务环境启动或测试行为。小改动不默认运行，失败保留材料与准确原因，不靠补拷本机缺失文件让结果变绿。实际入口及环境依赖由宿主明确配置。

`scripts/verify-clean-checkout.ps1 -ManifestFile <清单JSON> -Destination <尚不存在的隔离目录>` 执行这一操作。它会克隆指定仓库、执行明确的构建命令，并保留 checkout 和 evidence/result.json；这不是只读导出工具。清单格式：

```json
{
  "schemaVersion": "1.0",
  "repositories": [{"path": ".", "source": "仓库URL或本机Git仓库", "revision": "实际40位提交"}],
  "command": {"executable": "mvn", "arguments": ["-B", "-DskipTests", "test-compile"], "workingDirectory": ".", "timeoutSeconds": 1800},
  "environmentNotes": "说明实际工具链、依赖缓存及必要环境；禁止写入口令"
}
```

占位符必须替换。根仓库列第一项，嵌套仓库按父目录在前顺序列出并指定各自提交；路径必须位于隔离检出根下，且目标目录不存在。唯一例外是父仓索引明确声明且提交匹配的空 gitlink 占位目录；工具校验后填充，不递归删除已有目录。检出和审查入口拒绝经过链接的后代路径，避免不同平台中间目录链接解析差异。

工具不会自动拉取子模块或猜测未登记依赖，也不会删除失败目录。外部清单只读一次，原字节摘要、保留快照和实际命令来自同一版本。输出成功前核对构建命令的含义；命令返回零本身不证明执行了测试。仓库URL与命令参数可能出现在私有日志或清单中，应使用凭据管理器及环境注入，不将秘密写入清单。导出只排除约定的结构字段，不承诺自动识别作者写进标题或目标等自由文字中的秘密；分享前核对脱敏结果及版本映射。

## 声明交付材料的提交完整性（按需）

审查导出可加 `-DeliveryManifest <工作区相对路径>`，例如实际任务下的 `.ai-workspace/specs/features/<Feature>/tasks/<TaskId>/evidence-checksums.json`。清单沿用数组格式 `[{"path":"evidence/result.json","sha256":"实际64位SHA256"}]`；材料路径相对清单目录，不允许绝对路径、上级越界或链接后代。未传参数时 delivery=NOT_REQUESTED，不自动把所有 `.runtime` 日志当成交付义务，不增加完成门禁。

输出分别保留 declaredSha256、local 与 git 观察事实。COMMITTED 表示声明、本地字节和所记录本地提交中的原始 blob 三者一致；LOCAL 表示本地符合声明，但该提交中没有相同字节（包括未跟踪、仅暂存和 Git 换行/过滤转换后的不同内容）；CHANGED 表示本地不符合声明；MISSING 表示本地明确缺失，即使提交中仍有副本；无法核实路径、权限或 Git 时为 UNKNOWN。这些状态不证明已推送、远端可取、测试语义正确或任务可完成。

每个实际最近仓库固定一次 HEAD，支持嵌套仓库与 linked worktree，不用暂存区代替已提交内容。按原始 blob 字节比较，不运行 filters/textconv；已提交的符号链接和 gitlink 不当普通材料。结束时发现 HEAD 漂移会标为未知。清单摘要绑定原始字节（包括 UTF-8 BOM），解析使用同一份读取；顶层异常只影响 delivery，坏条目保留其他有效结果并标 coverage=INCOMPLETE。

Git 子进程关闭输入、有10秒执行及2秒输出排空预算，清理复用有界后台入口；单个blob超过64MiB或清理无法确认时保留缺口，不继续解释为完整交付。仓库 workingChanges 禁用配置中的外部 clean/smudge/process 过滤器，标注 EXTERNAL_FILTERS_DISABLED_SUBMODULE_WORKTREES_OMITTED；不递归检查子模块工作树的脏内容（仍保留 gitlink 提交差异），需要时通过显式 RepositoryPaths 或交付条目分别检查实际子仓；使用转换过滤器的工程应结合原始差异解释该观察，不把它等同于普通 Git 命令启用过滤器后的状态。
