# 验证续做与收尾

本指引不增加门禁或改变档位。先读取同一任务的 Status；有未结束验证或待入账结果时先 InspectRecovery。不要为继续工作新建任务、重拍基线、删除旧失败记录，或把过期会话 ID 当成当前身份。

## 固定验证批次

`Kind/Batch` 表示一个持续维护的验证目标，不是运行次数。相同测试的 RED、GREEN、修复后复测都复用同一个批次；每次 Run 有独立 runId，旧失败和日志仍保留。同一批次以最后一次真实执行为准，不同批次分别检查。命令、用例范围或 Profile 定义发生实际变化时带 Reason，说明变化及覆盖关系，不用理由跳过测试。

已经误建多个阶段批次的旧任务：列出每个批次的最新命令、用例和结果。保留历史，分别用原批次名执行正确的当前验证；需要修正命令或映射时明确 Reason。即便批次名带 red，也可在修复后重跑该批次取得 GREEN，不要故意制造失败。不能仅新增一个 final 批次来覆盖其他失败，也不能把更窄测试换进旧批次掩盖未修问题。当前没有批次合并/删除接口，勿手改 task.json。

## 命令与覆盖

- 优先使用宿主已定义的 Profile，参数数组由配置读取。
- 临时命令在 PowerShell 内用 `& ./ai-sop.ps1 ... -Arguments @('-NoProfile','-File','./scripts/test.ps1')`。外层若是 `pwsh -File`，它不会解析逗号数组；不要传入一个形如 `"'/d','/c','build.cmd'"` 的字符串。也不要用字符串求值补救。
- SetCaseScope 指定任务必须验证哪些用例；Run 的 CaseIds / JUnit 映射指定此次实际验证哪些用例，两者不可互相替代。一个测试类退出 0 不代表它覆盖全部业务用例。核实断言和测试输出后登记，JUnit 模式使用精确 classname/name 映射。
- 运行前确定命令和映射；代码或测试源继续变化后旧证据过期属正常行为。查看 STALE_EVIDENCE 的具体路径，不排除业务源码来维持旧证据。

## 交接与最后一轮

1. 父会话使用自己的真实 Hook 身份 Resume；只有 InspectRecovery 要求时才 Recover，确认旧执行停止，不让子会话接管父任务。已撤销委派不会随 Resume 恢复。需要修改时重新 Join → Delegate，具体见 [显式委派](EXECUTION_DELEGATION.md)。
2. 最后一轮实现/测试修改后，先编译，再独立复审。只读审查者返回报告，不 Join/Resume/认领任务。审查发现问题时回到同一任务的修复循环。
3. 修改结束、审查通过后，核对本任务用例范围、规格和影响摘要；在最终代码上运行适用编译和全部仍需通过的批次。不要仅因历史阶段命名而扩大到整个项目测试，也不要遗漏已有批次的验证目标。
4. 子会话验证停止后由父会话撤销委派，完成适用的 ReviewImpact、文档同步及收尾审查，执行 Task Complete。后续如再修改源码/测试或测试定义，应重新验证受影响证据。

会话到期是身份恢复事项，不能将真实测试失败改写为会话问题。缺独立复审、未覆盖必测用例或尚有失败时，如实报告未完成；有已授权的下一步则继续执行，不只留一句“下一步复审”就结束整个开发任务。
