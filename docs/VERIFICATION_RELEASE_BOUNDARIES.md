# 验证与发布的证据边界

本说明补充现有 T1/T2/T3，不新增档位、批准、Task Complete 条件或历史重验义务。宿主已有的特定审核约定仍按适用范围执行。

## 证据对应的对象

| 证据 | 可支持的结论 | 不覆盖 |
|---|---|---|
| 输入清单及 SHA-256 | 所声明输入的版本与变化 | 内容正确、作者身份、备份恢复 |
| 编译及目标用例报告 | 指定输入与命令在本次执行的结果 | 未运行用例、外部服务已加载新版本 |
| 运行目标观察 | 采集时指定实例报告的构建、配置、数据环境 | 未观察的实例、报告真实性的独立认证 |
| 持久化冷重载 | 已提交数据可以重新加载 | 提交前崩溃时的业务承诺 |
| 发布观察与恢复演练 | 指定版本、环境及故障场景下的结果 | 所有未来故障、全体历史任务重新验收 |

需要联调或发布结论时，由宿主入口记录期望制品及实际运行目标，关联源码、产物、配置、协议、隔离数据和场景。输入指纹不会自动覆盖外部环境。缺少目标观测时明确未核验，不把固定版本字符串或手填预期复制成实际观测。

## 业务验证

从已确认规则导出预期，再选择相关测试。优先复用真实入口与夹具；准备、操作、断言、清理分开。按风险检查重复、并发、超时、部分成功、保存前后中断、旧数据与版本混跑；不机械执行全部测试。

资源生命周期还需关注补救自身失败及控制器退出后换执行者恢复，按实际链路选关键组合。跨任务发现、派生审查材料、验证入口副作用说明及按需干净检出的方法见 [发现追踪与审查材料](REVIEW_AND_FINDINGS.md)，不增加默认完成条件。

持久化机制由宿主决定。保存完成后的冷重载与成功响应后、提交前崩溃分别取证；未确认的持久化承诺应写 UNKNOWN，不能默认为零丢失或允许丢失。内存替身只证明相应进程内行为。

## 发布与恢复

开发任务 DONE 与生产发布结果分开记录。实际发布时在宿主发布记录中关联：制品/配置/协议版本、数据迁移及兼容窗口、灰度分组、指标阈值与观察时间、停止条件、可执行恢复路径、负责人和证据位置。测试通过的制品应直接晋级，重新构建则重新关联验证。

有状态变更分别验证新读旧、旧读新、旧版本回写，以及降级后继续写入。不可安全回退时先停止放量或关闭相应能力，选择兼容修复/补偿；不自动恢复整库。数据备份须有可恢复内容，并确认恢复耗时、可接受损失窗口及对新增合法数据的处理。演练按发布风险和维护周期安排，不加入每次小修改。

失败、阻塞、未执行、不适用分别报告；不适用须有依据，环境缺失不能冒充不适用。归档复用现有任务/发布记录，保留失败历史，不增加重复证据账本。
